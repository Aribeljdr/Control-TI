================================================================================
  1. PREPARACIÓN INICIAL
================================================================================

PASO 1: Verificar el Sistema
-----------------------------
1. Ejecutar: verificar-sistema.bat
2. Verificar que todos los checks estén en ✅
3. Si hay errores ⚠️, corregirlos antes de continuar

PASO 2: Iniciar MongoDB
-----------------------
Opción A - MongoDB Local:
  Windows Service: net start MongoDB
  Manual: mongod --dbpath "C:\data\db"

Opción B - MongoDB Atlas:
  Asegurarte que el connection string en backend/.env sea correcto

PASO 3: Iniciar el Sistema
--------------------------
1. Ejecutar: iniciar-sistema-completo.bat
2. Esperar que aparezcan 2 ventanas:
   - Ventana 1 (Backend): Debe mostrar "🚀 Servidor iniciado correctamente"
   - Ventana 2 (Frontend): Debe mostrar "VITE ... ready in ... ms"

3. Verificar URLs:
   Backend: http://localhost:5000
   Frontend: http://localhost:3000

PASO 4: Abrir el Navegador
--------------------------
1. Abrir Chrome/Edge/Firefox
2. Ir a: http://localhost:3000
3. Abrir DevTools (F12) para ver la consola

✅ VALIDACIÓN:
- El navegador carga sin errores 404
- La consola no muestra errores críticos en rojo
- El sistema muestra la pantalla de Splash

✅ VALIDACIÓN:

⚠️ SI ALGO FALLA:

================================================================================
  4. PANTALLA DE LOGIN
================================================================================

DESCRIPCIÓN:
Pantalla de autenticación donde los usuarios ingresan sus credenciales.

QUÉ DEBERÍAS VER:
-----------------
- Título: "Iniciar Sesión" o "Mantenimiento Preventivo IT"
- Campo de texto: "Usuario"
- Campo de contraseña: "Contraseña"
- BOTÓN: "Iniciar Sesión"
- Mensaje de error (solo si login falla)

CAMPOS DEL FORMULARIO:
---------------------
┌─────────────────────────────────────────────────────────────┐
│ [Usuario]                                                   │
│ ¿Qué es?: Nombre de usuario para login                     │
│ ¿Qué acepta?: Texto alfanumérico                           │
│ ¿Validación?: Requerido, no puede estar vacío             │
│ Ejemplo: "soporteti"                                        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ [Contraseña]                                                │
│ ¿Qué es?: Contraseña del usuario                           │
│ ¿Qué acepta?: Texto (oculto con •••••)                    │
│ ¿Validación?: Requerido, no puede estar vacío             │
│ Ejemplo: "admin2025"                                        │
└─────────────────────────────────────────────────────────────┘

BOTONES Y QUÉ HACEN:
-------------------
┌─────────────────────────────────────────────────────────────┐
│ [Iniciar Sesión]                                            │
│ ¿Qué hace?: Envía credenciales al backend para autenticar  │
│ ¿Cómo funciona?:                                            │
│   1. Valida que los campos no estén vacíos                  │
│   2. Envía POST a /api/auth/login                           │
│   3. Si es correcto: Guarda token y redirige a Dashboard    │
│   4. Si es incorrecto: Muestra mensaje de error             │
└─────────────────────────────────────────────────────────────┘

CREDENCIALES POR DEFECTO:
-------------------------
Usuario: soporteti
Contraseña: admin2025
Rol: admin

✅ VALIDACIÓN - CASO EXITOSO:
1. Escribir: soporteti
2. Escribir: admin2025
3. Click en "Iniciar Sesión"
4. Debe mostrar carga/loading
5. Debe redirigir al Dashboard
6. NO debe mostrar errores

✅ VALIDACIÓN - CREDENCIALES INCORRECTAS:
1. Escribir usuario incorrecto: "usuarioerroneo"
2. Escribir contraseña: "12345"
3. Click en "Iniciar Sesión"
4. DEBE mostrar mensaje: "Credenciales inválidas"
5. NO debe redirigir
6. Los campos deben permanecer

✅ VALIDACIÓN - CAMPOS VACÍOS:
1. Dejar campos vacíos
2. Click en "Iniciar Sesión"
3. DEBE mostrar validación de campos requeridos
4. NO debe enviar request al backend

VERIFICAR EN CONSOLA DEL NAVEGADOR:
-----------------------------------
Al hacer login exitoso, deberías ver en DevTools (F12):
- POST http://localhost:5000/api/auth/login → Status 200
- localStorage debe tener 'mp_auth_session' con el token

VERIFICAR EN BACKEND:
--------------------
En la ventana del backend deberías ver:
- Log del request POST /api/auth/login
- Status 200 si fue exitoso
- Status 401 si las credenciales son incorrectas

⚠️ SI ALGO FALLA:
- Error "Network Error": Backend no está corriendo
- Error 401: Credenciales incorrectas
- No redirige: Revisar consola del navegador

PRUEBA 1: Crear Nuevo Equipo
----------------------------
1. Click en "+ Nuevo Equipo"
2. Debe abrir modal/formulario
3. Seleccionar Tipo: "PC"
4. El código debe auto-generarse (ej: PC-001)
5. Llenar campos:
   - Hostname: "TEST-PC-001"
   - Usuario: "Usuario Prueba"
   - Área: "IT"
   - Fecha Compra: Hoy
   - Próximo Mantenimiento: En 3 meses
6. Click "Guardar"
7. Debe cerrar el modal
8. Debe aparecer el nuevo equipo en la lista
9. Verificar en backend: POST /api/equipments → Status 201

PRUEBA 2: Buscar Equipo
-----------------------
1. En la barra de búsqueda escribir: "TEST"
2. Debe filtrar y mostrar solo equipos con "TEST"
3. Borrar búsqueda
4. Debe mostrar todos los equipos de nuevo

PRUEBA 3: Filtrar por Área
--------------------------
1. Click en filtro "Área"
2. Seleccionar "IT"
3. Debe mostrar solo equipos del área IT
4. Seleccionar "Todas"
5. Debe mostrar todos los equipos

PRUEBA 4: Filtrar por Estado
----------------------------
1. Click en filtro "Estado"
2. Seleccionar "OK"
3. Debe mostrar solo equipos con estado OK
4. Seleccionar "Todos"

PRUEBA 5: Editar Equipo
-----------------------
1. Click en "✏️ Editar" de un equipo
2. Debe abrir modal con datos actuales
3. Cambiar el hostname a "TEST-PC-EDITADO"
4. Click "Guardar"
5. Debe actualizar y mostrar nuevo nombre
6. Verificar en backend: PUT /api/equipments/:id → Status 200

PRUEBA 6: Ver Detalles
----------------------
1. Click en "👁️ Ver Detalles"
2. Debe navegar a página de detalle
3. Ver siguiente sección (DETALLE DE EQUIPO)

PRUEBA 7: Eliminar Equipo
-------------------------
1. Click en "🗑️ Eliminar" de un equipo
2. Debe mostrar modal de confirmación
3. Click "Cancelar" → No debe eliminar
4. Click "🗑️ Eliminar" de nuevo
5. Click "Confirmar" → Debe eliminar
6. Equipo desaparece de la lista
7. Verificar en backend: DELETE /api/equipments/:id → Status 200

  7. MÓDULO: DETALLE DE EQUIPO
================================================================================

DESCRIPCIÓN:
Vista detallada de un equipo específico, mostrando toda su información,
componentes, historial de mantenimientos y periféricos asignados.

RUTA: /equipment/:id

CÓMO LLEGAR:
------------
1. Ir a Inventario
2. Click en "👁️ Ver Detalles" de cualquier equipo

QUÉ DEBERÍAS VER:
-----------------
- Botón "← Volver" (regresa al inventario)
- Foto del equipo (si tiene)
- Información general del equipo
- Componentes técnicos (CPU, RAM, Disco, etc.)
- Riesgos identificados
- Periféricos asignados (Mouse, Teclado, Monitor)
- Historial de mantenimientos
- BOTÓN: "Editar Equipo"
- BOTÓN: "Registrar Mantenimiento"

SECCIONES DE LA VISTA:

1. INFORMACIÓN GENERAL
---------------------
Muestra:
- Código del equipo
- Hostname
- Usuario asignado
- Área
- Marca y Modelo
- Número de Serie
- Sistema Operativo
- Fecha de Compra
- Estado actual (OK/Riesgo/Crítico)
- Último mantenimiento
- Próximo mantenimiento
- Recomendación

2. COMPONENTES TÉCNICOS
----------------------
Si el equipo es PC/Laptop/AIO, muestra:
- CPU: Modelo y Año
- RAM: Modelo y Año
- Disco: Modelo y Año (SSD/HDD)
- Motherboard: Modelo y Año
- PSU: Fuente de poder (opcional)
- GPU: Tarjeta gráfica (opcional)
- Monitor: Pantalla (si es AIO)

3. RIESGOS IDENTIFICADOS
-----------------------
Lista de checkboxes mostrando:
- ⬜ Lentitud del sistema
- ⬜ Reinicios inesperados
- ⬜ Salud del disco
- ⬜ Temperatura alta
- ⬜ Problemas de pantalla
- ⬜ Problemas de red
- ⬜ Problemas de software

✅ = Tiene ese riesgo
⬜ = No tiene ese riesgo

PRUEBAS DE SEGURIDAD BÁSICAS:

PRUEBA 1: Protección de Rutas
-----------------------------
1. Cerrar sesión (logout)
2. En la barra de direcciones, ir a: http://localhost:3000/dashboard
3. NO debe mostrar dashboard
4. DEBE redirigir a Login
5. Mismo con /inventory, /bitacora, etc.

PRUEBA 2: Expiración de Token
-----------------------------
1. Hacer login
2. Esperar 7 días (o modificar JWT_EXPIRE a 1m para probar)
3. Intentar hacer alguna operación
4. DEBE mostrar error de token expirado
5. DEBE obligar a hacer login de nuevo

PRUEBA 3: Validación de Campos
------------------------------
1. Intentar crear equipo sin campos requeridos
2. DEBE mostrar error de validación
3. NO debe enviar request al backend
4. Llenar solo algunos campos
5. Intentar guardar
6. DEBE indicar qué campos faltan

PRUEBA 4: SQL Injection Básico
------------------------------
1. En campo de login, usuario: admin' OR '1'='1
2. Password: cualquiera
3. NO debe permitir login
4. DEBE rechazar con error

PRUEBA 5: XSS Básico
--------------------
1. Crear equipo con nombre: <script>alert('XSS')</script>
2. Guardar
3. Ver lista de equipos
4. NO debe ejecutar el script
5. DEBE mostrar el texto literal

✅ VALIDACIÓN:
Si todas estas pruebas fallan (no permiten ataque), la seguridad básica
está funcionando correctamente.
